# 판정 규칙 (rules)

## 왜 만드는가

실험 1~4 이후에도 남은 오답은 답변 모델이 원문을 매번 새로 해석하면서 생긴다.

- 예외 조항: 휴학생 제외, 단 방통대는 가능
- 이름이 비슷한 항목: 건강보험료와 보험료 납부
- 조건: 계좌이체는 증빙을 내야 인정

프롬프트 규칙 추가로는 줄지 않았다([EXP4_CONCLUSION_LINE_DEV.md](../../benchmarks/EXP4_CONCLUSION_LINE_DEV.md)).
답변 모델을 gpt-5.4-mini로 바꾸면 조건부를 불가로 읽는 오답은 줄었지만, 위험 허용이 다시 생기고 실행 간 결론 바뀜도 늘었다(p=0.30, [EXP5_ANSWER_MODEL.md](../../benchmarks/EXP5_ANSWER_MODEL.md)).
그래서 규칙 계층의 목적은 "모델로는 안 된다"가 아니라 결정성, 안전성, 추적 가능성이다.

## 결정 사항

- **무엇이 있는가**는 YAML 메타데이터로 선언한다.
  - 대상: 지출 항목, 결제 방식, 사용 불가 업종, 자격 요건, 제외 대상, 자격 상실 사유
  - 각 항목에 쪽수와 원문 인용을 붙인다.
- **어떻게 판정하는가**는 핸들러 코드가 맡는다. 결정적으로 동작하고 단위 테스트를 둔다.
- **LLM은 두 가지만 한다.**
  - 질문을 선언된 규칙 ID에 연결한다.
  - 핸들러가 정한 결론을 바꾸지 않고 문장으로 쓴다.
- 규칙에 걸리지 않는 질문과 정보성 질문은 기존 RAG 경로로 간다.
- 범위는 판정 질문만이다. 지출(8·12~18·31쪽)과 자격(7·9쪽)을 다룬다. 책자 전체를 모델링하지 않는다.
- 시험셋 실패 문항만 골라 규칙을 만들지 않는다. 해당 쪽 전체를 옮긴다.
- 원문 인용은 `tests/test_rules.py`가 OCR 원문과 대조해 검사한다. `Data/`가 없는 환경에서는 건너뛴다.
- 인덱스와 청킹은 바꾸지 않는다. 고정 기준선 인덱스 `18fec50`을 그대로 쓴다.
- 기존 결과와 비교할 수 있도록 스위치를 둔다(`RULES_ENABLED`, 예정).

## 남은 일

1. [x] **규칙 검토 (사람, 2026-10-31):** 107행 중 O 100, X 7.
   - X 7건은 모두 반영했다.
     - 책자만으로 범주를 단정할 수 없는 별칭은 `unverified_aliases`로 옮겼다. 해당: 토스페이 등 간편결제, 해외 직구, 교통카드 충전, 피부과 시술.
     - 코인은 "가상자산 투자 목적 매수"로 바꿨다.
     - 이월과 개인 돈 입금은 `account_actions`로 분리했다. 카드 결제 판정은 범주가 맞지 않아서다.
   - `health_insurance`의 계좌이체 판정은 unclear로 유지한다. 담당 기관 확인이 필요하다.
2. [x] **핸들러** (`handlers.py`, `tests/test_rule_handlers.py`)
   - `resolve_spending(rule_id, payment)`: 결제 방식 금지 → 사용 불가 업종 → 계좌 이용 → 항목×경로(카드/이체/보전) 순서로 판정한다.
     - 결제수단을 모르면 가장 유리한 경로를 쓴다. 예: 해외 AI 구독은 보전 경로로 조건부.
   - `check_eligibility(section, rule_id, exception_id, age)`: 제외 사유의 예외에 해당해도 "가능"이 아니라 조건부다. 다른 요건이 남아 있기 때문이다.
   - 요건 내용만 묻는 질문과 미확인 별칭은 unclear로 처리해 RAG로 넘긴다.
3. [x] **질문 → 규칙 연결기** (`mapper.py`, `tests/test_rule_mapper.py`)
   - LLM은 규칙 ID, 결제 경로, 나이, 예외만 뽑는다. 결론은 핸들러가 정한다.
   - `validate_match`가 선언되지 않은 ID·예외·결제 경로를 걸러 RAG로 넘긴다.
   - **결정적 안전장치 2개.** 프롬프트만으로는 실행마다 결과가 흔들려서 넣었다.
     - `blocked_merchant_entry`: 구매 대상이 업종 표의 어느 항목인지 먼저 쓰게 한다. 표에 실제로 있는 이름이면 불가로 고정한다.
       - 막는 오답: 금목걸이를 면접용, 오토바이를 배달 알바용이라는 이유로 허용한 경우.
     - 금지 규칙 이름이 질문에 그대로 있는데 다른 허용 규칙에 연결되면 결론을 내지 않고 RAG로 넘긴다.
       - 막는 오답: "소액결제…통신비니까"를 통신비로 처리한 경우.
   - **모델:** gpt-4.1-mini (`OPENAI_RULE_MAPPER_MODEL`). gpt-4o-mini는 예외를 지어내 허용 쪽으로 틀렸다.
     - 예: 일반 대학원 진학에 방통대 예외를 붙였다.
   - **개발셋** (`benchmarks/datasets/rule_mapping_dev_v1.jsonl`, 71문항)
     - 구성: 결론 개발셋 34 + 검색 개발셋의 정보 질문 37
     - 정답은 "규칙 계층이 내야 할 결론"이다. 규칙 대상이 아니면 unclear다.
     - 정답은 주 작업자(Claude)가 YAML 기준으로 달았다. 사람 검토는 받지 않았다.
   - **결과** (`run_rule_mapping_dev.py`, gpt-4.1-mini)

     | 버전 | 결론 일치 | 잘못 끼어듦 (규칙 대상 아님 23개 중) | 규칙 처리 |

     - 남은 불일치 3개:
       - d03 증빙 질문, d13 소액결제: 결론을 내지 않고 RAG로 넘어간다.
       - retrieval-010 "생성형 AI 구독료 해외결제" 키워드 질의: 해외결제를 결제 방식으로 보고 불가로 답했다.
     - **한계:** 개발셋을 보면서 프롬프트를 4번 고쳤다. 그래서 68/71은 낙관적인 수치다. 일반화 여부는 시험셋 v1·v2에서 본다.
   - 검토 의견(프롬프트에 반영함. 핸들러는 연결 결과만 받으므로 여기서 지켜야 한다):
