# 실험 4: 결론 첫 줄 강제 (개발셋에서 중단)

시험셋까지 가지 않았다. 개발셋에서 효과가 없어 프롬프트 변경을 되돌렸다.

## 문제

- 실험 3b 이후 시험셋에서 계속 틀리는 문항은 19개다.
  - 조건부 질문에 "불가"로 답한 경우 5개
  - 정상 질문에 "불가"로 답한 경우 4개
- 답변에 결론이 흐릿하게 드러나거나, 다른 항목의 불가 근거를 질문 대상에 잘못 적용하는 사례가 보였다.

## 시도

`POLICY_CONTEXT_SYSTEM_PROMPT`에 세 가지를 넣었다.

- 첫 줄을 "결론: 가능 / 조건부 가능 / 불가 / 확인 필요" 중 하나로 쓰게 했다.
- 결론을 정하는 순서를 4단계로 정했다.
  1. 직접 불가 근거가 있으면 불가
  2. 조건이 붙은 가능 근거가 있으면 조건부 가능
  3. 조건 없는 가능 근거가 있으면 가능
  4. 근거가 없으면 확인 필요
- 다음 두 경우에는 "불가"라고 쓰지 않게 했다.
  - 다른 항목의 불가 근거만 있는 경우
  - 사용 가능 목록에 이름이 없을 뿐인 경우

## 개발셋 결과 (`eval_dev_v1.jsonl`, n=34, 3회)

| 지표 | 실험 3b | 실험 4 |
|---|---|---|
| 결론 정확도 | 27, 29, 28 | 29, 29, 27 |
| 위험 허용 (n=21) | 0, 0, 0 | 0, 0, 0 |

3회 범위가 겹친다. 순효과가 없다.

## 남은 오답에서 본 것

- **d02:** "결론: 가능"이라고 쓰고, 바로 아래에 필요한 증빙을 나열했다. 사실상 조건부인데 결론 줄과 본문이 어긋났다.
- **d08:** "재학생 및 휴학생 제외 (단, 방송통신대학 … 신청 가능)"의 예외 문장을 잘못 읽었다.
- **d18:** 사용 가능한 "건강보험료"와 사용 불가인 "보험료 납부"를 혼동했다.

## 결론

- 남은 오류는 답변 모델이 원문을 해석하는 단계에서 생긴다. 예외 조항, 이름이 비슷한 항목, 조건 해석이 그렇다. 매번 원문을 새로 해석하는 한, 프롬프트에 규칙을 더 넣어도 이 오류는 줄지 않았다.
- 프롬프트 변경은 서비스 코드에 넣지 않았다.
- 다음 시도는 판정 규칙을 메타데이터로 선언하고, 결론은 코드로 정하는 구조다. 관련 파일은 `app/rules/TODO.md`에 있다.
