# 실험 7: 판정 규칙 계층

## 왜 했나

- 실험 6에서 실험 3b의 다수결 오답 19개를 원인별로 나눴다.
  - 검색·관문 9: 근거를 못 찾았거나 차단 관문에서 잘렸다.
  - 판단 9: 근거는 있었는데 답변 모델이 조건부를 불가로 읽는 식으로 틀렸다.
  - 의도 분류 1: t096. 질문이 RAG 경로로 오지 않았다.
- 답변 모델을 올리면(실험 5) 판단 오답 일부가 줄었지만 위험 허용과 결론 바뀜이 늘었다.
- 책자 전체를 넣으면(실험 6) 검색 손실은 사라졌지만 지어내기가 늘었다.
- 그래서 "쓸 수 있나요/대상인가요" 판정 질문만 떼어 내어 규칙으로 답하게 했다.
  - 구조(항목·결제 방식·업종·자격 요건)는 YAML 메타데이터로 선언한다. 사람 검토 107행을 거쳤다.
  - 판정은 결정적 핸들러가 한다.
  - LLM(gpt-4.1-mini)은 질문을 규칙 ID에 연결만 한다.
  - 규칙에 걸리지 않으면 기존 RAG로 간다.
- 설계와 개발셋 결과는 [app/rules/TODO.md](../app/rules/TODO.md)에 있다.

## 조건

- **기준:** 실험 3b(`restriction_query`)
- **변경:** `RULES_ENABLED=true` 하나. 의도 분류 뒤에 `resolve_rules` → `generate_rule_answer`를 넣었다.
  - 규칙 경로 답변은 템플릿이다(답변 LLM 호출 없음).
  - 결론이 unclear이거나 연결기가 실패하면 기존 경로 그대로다.
- **유지:** 인덱스, 검색, 키워드 차단, 근거 평가, 답변 모델 gpt-4o-mini, 판정 모델 gpt-4.1
  - 규칙과 겹치는 기존 특수 처리(배달앱 지침, 키워드 차단 목록 등)도 지우지 않았다. 두 변경이 섞이지 않게 하려고서다.
- **실행:** 시험셋 v1 109문항, 3회. 검색 결과 파일은 실험 3b 것을 복사해 썼다.
- **튜닝:** 연결기 프롬프트는 개발셋(`rule_mapping_dev_v1`, 결론 개발셋 34)으로만 고쳤다. 시험셋을 본 뒤에는 고치지 않았다.
- 첫 시도는 OpenAI 크레딧 소진으로 중간에 끊겨서 버리고 처음부터 다시 돌렸다. 다시 돌린 3회에는 오류가 0개다.

### 규칙 경로만 따로

- 규칙이 답한 문항: 실행마다 44, 44, 42개 (109개 중). 모두 판정 문항(73개)이다. 정보 질문에는 끼어들지 않았다.
- 3회 중 2회 이상 규칙이 답한 판정 문항 43개 중 다수결 정답 40개. RAG로 간 30개는 22개.
- 규칙 경로에서는 실행 간 결론이 바뀐 문항이 없다. 남은 13개 바뀜은 모두 RAG 경로다.
  - t028은 3회 중 1회만 규칙으로 갔다. 결론은 같았다.
- 응답 시간 중앙값: 규칙 경로 1.8초, RAG 경로 12.9초.

## 규칙 경로 오답 3개 (모두 연결기 오류)

핸들러와 YAML은 맞았고, 질문을 규칙에 잘못 연결했다.

| 문항 | 정답 | 연결 | 원인 |
|---|---|---|---|
| t097 교통카드 기능으로 버스 | 가능 | `easy_pay` → 불가 | 교통카드를 간편결제로 연결했다. "교통카드 충전"은 미확인 별칭인데 질문 문구가 달라 결정적 검사에 안 걸렸다 |
| t046 통신비 이체, 결제대행요금 포함 | 조건부 | `telecom` + 조건 위반 → 불가 | 일부만 제외되는 경우를 전체 위반으로 표시했다. 프롬프트에 금지했는데도 그랬다 |
| t104 "기프티콘은 안 된다면서요, 그럼 카페 커피는요?" | 가능 | `gift_card` → 불가 | 앞 문장의 금지 항목에 연결했다. 실험 3b에서는 맞혔던 문항이라 유일한 망가짐이다 |

- 세 개 모두 허용을 불가로 바꾼 쪽이다. 위험 허용은 0이다.
- 시험셋에서 본 문항이라 프롬프트를 고치지 않았다. 고치면 이 수치가 낙관적이 된다.

## 결론

- 판정 질문의 약 60%를 규칙이 맡았고, 거기서 결론 정확도 40/43, 실행 간 바뀜 0, 응답 1.8초다.
- 전체 결론 정확도는 56 → 62, 위험 허용 0을 유지했다. 표본 73개에서 p=0.02다.
- 남은 오답은 대부분 규칙 범위 밖(RAG 경로)이다. 규칙을 늘릴지, RAG 쪽을 손볼지는 원인별로 따로 정한다.

## 한계

- 시험셋 v1은 실험 1~6 동안 여러 번 봤다. 연결기 프롬프트는 개발셋으로만 고쳤지만 YAML 규칙의 범위는 책자 쪽 단위로 정했고, 시험셋 문항이 그 범위 결정에 영향을 줬을 수 있다. 최종 수치는 아직 쓰지 않은 시험셋 v2로 다시 잰다.
- 정답 라벨과 판정은 gpt-4.1 판정기를 썼다. 사람 검토는 실험 1 때 표본으로만 했다.
- 연결기 오류 3개는 같은 유형(앞 문장·비슷한 이름에 끌림)이라 v2에서도 나올 수 있다.
- 기존 특수 처리를 지우지 않아서 서비스 구조는 아직 복잡하다. 정리는 별도 변경으로 한다.
