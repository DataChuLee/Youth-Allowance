# v1 → v4 정책·안전성 벤치마크 결과

## 비교 조건

- 동일한 `policy_safety_v1.jsonl` 13문항을 사용했다.
- v1은 `retrieve → LLM evidence grading → policy resolution` 순서였다.
- v4는 명시적 제한 질문에 대해 정책 규정 용어로 검색한 뒤, PDF 근거가 확인되면 LLM query planner와 evidence grader를 건너뛰고 `blocked_by_policy`로 분기한다.
- 두 실행 모두 로컬 FAISS 인덱스와 OpenAI API를 사용했다. 네트워크 지연의 영향을 받으므로, 지연 시간은 시드셋 수준의 관측치로만 해석한다.

| 지표 | v1 | v4 | 변화 |
| --- | ---: | ---: | ---: |
| 상태 정확도 | 84.6% (11/13) | 100.0% (13/13) | +15.4%p |
| 안전 경로 위반율 | 12.5% (1/8) | 0.0% (0/8) | -12.5%p |
| 출처 적중률* | 100.0% (5/5) | 100.0% (5/5) | 유지 |
| 전체 평균 지연 | 27.67초 | 9.16초 | -66.9% |
| 전체 p50 지연 | 29.61초 | 12.29초 | -58.5% |
| 전체 p95 지연 | 31.51초 | 19.54초 | -38.0% |

\* 출처 적중률은 허용 가능한 `chunk_id`를 수동 라벨링한 5개 답변 가능/조건부 사례에만 적용한다.

## 정책 제한 시나리오 상세

정책 제한 5문항(상품권, 카카오페이, 중고거래, ATM 현금 인출, 게임)은 v1에서 상태 정확도 60.0%(3/5)였고, v4에서 100.0%(5/5)로 개선됐다.

- v1 평균 지연: 30.70초
- v4 평균 지연: 0.85초

v4에서 카카오페이는 `sem_0032`, 중고거래와 상품권은 `sem_0018`, ATM 현금 인출은 `sem_0034` 근거를 반환했다. 이는 정책 규정 쿼리를 일반 의미 검색과 분리하고 BM25 비중을 높인 효과다.

## 해석과 한계

- 이 결과는 13개 시드 문항의 회귀·파일럿 평가다. 포트폴리오 대표 성과로 쓰기 전에는 정책·안전성 150문항 이상으로 확대해야 한다.
- 상태 정확도는 시스템 제어 품질을 뜻하며, 답변 문장 전체의 사실성이나 사용자 만족도를 직접 의미하지 않는다.
- 현재 `source_hit_rate`는 답변 가능/조건부 5문항에만 라벨이 있다. 정책 제한과 근거 부족 사례의 출처 품질 라벨을 추가해야 한다.
