# 청년수당 RAG 챗봇 PRD

## 1. 개요

이 프로젝트는 `Data/청년수당 참여자 안내책자.pdf`를 기준 문서로 사용하는 **참여자용 FAQ 챗봇**을 만든다.

참여자는 안내책자를 직접 열어 검색하지 않아도 웹 채팅 화면에서 청년수당 관련 정보를 확인할 수 있다. 첫 버전은 로컬 MVP이며, RAG 기반으로 PDF 근거를 검색하고 OpenAI 모델로 답변을 생성한다. 답변에는 항상 출처 페이지와 관련 문단 일부를 함께 표시한다.

## 2. 문제 정의

청년수당 참여자는 카드 사용처, 활동기록서, 증빙, 자격상실, 참여 중단 등 여러 정보를 빠르게 확인해야 한다. 하지만 현재 기준 자료가 PDF 안내책자이기 때문에 필요한 내용을 매번 직접 찾는 과정이 번거롭다.

챗봇은 이 PDF를 대화형 인터페이스로 바꾸되, 정책성 정보의 특성상 추측 답변을 피하고 근거를 함께 보여줘야 한다.

## 3. 대상 사용자

- 청년수당 참여자: 안내책자 기준으로 빠르게 FAQ성 답변을 확인하려는 사용자.
- 개발자 또는 프로젝트 관리자: 로컬 환경에서 PDF 기반 RAG 챗봇을 검증하려는 사용자.

MVP는 공개 운영 서비스가 아니라 로컬 개발 및 데모를 목표로 한다.

## 4. 목표

- 참여자가 사용할 수 있는 웹 기반 채팅 UI를 제공한다.
- `청년수당 참여자 안내책자.pdf`를 1차 근거로 답변한다.
- 모든 정상 답변에 PDF 페이지 번호와 관련 문단 excerpt를 표시한다.
- OpenAI API로 임베딩과 답변 생성을 수행한다.
- LangChain으로 PDF 로딩, 청크 분할, 임베딩, Chroma 연동을 처리한다.
- LangGraph로 질문 처리 흐름을 구성한다.
- `.env`에 LangSmith 설정이 있으면 추적을 활성화한다.
- 대화 기록은 브라우저 세션 상태에만 유지한다.
- 향후 공식 출처 웹 검색을 붙일 수 있는 구조를 남긴다.

## 5. 범위 제외

- 사용자 계정 기능은 구현하지 않는다.
- 대화 기록을 서버 DB에 저장하지 않는다.
- 공개 배포는 MVP 범위에 포함하지 않는다.
- 외부 웹 검색 기능은 MVP에서 실제로 동작하지 않는다.
- 관리자용 재색인 화면은 만들지 않는다.
- 일반 웹 전체를 근거로 답변하지 않는다.

## 6. MVP 범위

MVP는 다음을 포함한다.

- FastAPI 백엔드.
- Next.js 프론트엔드.
- 로컬 Chroma 벡터 저장소.
- PDF indexing 명령.
- `GET /health` API.
- canonical `POST /api/v1/chat` API와 deprecated 호환 `POST /chat` API.
- `POST /api/v1/chat/stream` API.
- 채팅 UI.
- FAQ 빠른 질문 버튼.
- 답변별 출처 표시.
- PDF 근거가 부족할 때의 안전한 fallback 답변.

## 7. 사용자 경험

첫 화면은 랜딩 페이지가 아니라 바로 사용할 수 있는 챗봇 화면이다.

UI에는 다음 요소가 포함된다.

- 채팅 메시지 목록.
- 질문 입력창.
- 전송 버튼.
- 대표 질문을 바로 보낼 수 있는 FAQ 빠른 질문 버튼.
- 답변 생성 중 로딩 표시.
- 백엔드 연결 실패, 인덱스 없음, 답변 생성 실패에 대한 오류 상태.
- 챗봇 답변 아래의 출처 목록.
- 민감정보를 입력하지 말라는 짧은 안내 문구.

대화 기록은 브라우저 상태에만 저장한다. `thread_id`는 `sessionStorage`에 탭 단위로 유지하고, 최근 대화 최대 4개만 요청에 포함한다. 서버는 대화 기록을 저장하지 않는다.

## 8. 핵심 사용자 흐름

1. 개발자가 PDF indexing 명령을 실행한다.
2. 개발자가 FastAPI 백엔드를 실행한다.
3. 개발자가 Next.js 프론트엔드를 실행한다.
4. 참여자가 로컬 웹앱에 접속한다.
5. 참여자가 직접 질문하거나 FAQ 빠른 질문 버튼을 누른다.
6. 프론트엔드는 기본적으로 `POST /api/v1/chat/stream`으로 질문을 보내고, 필요 시 `POST /api/v1/chat` JSON API를 사용할 수 있다.
7. 백엔드는 FAISS와 BM25 결과를 RRF로 결합해 관련 PDF 청크를 검색한다.
8. LangGraph가 검색 근거가 충분한지 판단한다.
9. 근거가 충분하면 PDF 근거만 사용해 답변을 생성한다.
10. 근거가 부족하면 안내책자에서 확인되지 않는다고 답하고, 향후 공식 출처 확인이 필요할 수 있음을 표시한다.
11. 프론트엔드는 답변과 출처를 표시한다.

## 9. 기능 요구사항

### 9.1 PDF Indexing

- 시스템은 `Data/청년수당 참여자 안내책자.pdf`를 읽어야 한다.
- 페이지 단위 텍스트를 추출해야 한다.
- 추출한 텍스트를 검색 가능한 청크로 나눠야 한다.
- 각 청크에는 다음 메타데이터가 있어야 한다.
  - PDF source 또는 title.
  - page 번호.
  - chunk_id.
  - chunk text.
- OpenAI embeddings로 벡터를 생성해야 한다.
- 벡터와 메타데이터를 로컬 Chroma 디렉터리에 저장해야 한다.
- PDF가 없거나 읽을 수 없으면 명확한 오류를 반환해야 한다.
- indexing 완료 후 다음 품질 지표를 콘솔에 출력해야 한다.
  - 전체 페이지 수.
  - 텍스트가 추출된 페이지 수.
  - 텍스트가 비어 있는 페이지 수.
  - 전체 추출 문자 수.
  - 생성된 청크 수.
  - 샘플 청크 2~3개와 해당 page, chunk_id.
- 텍스트가 비어 있는 페이지가 많거나 전체 추출 문자 수가 비정상적으로 작으면 indexing은 실패로 처리해야 한다.
- MVP는 OCR을 구현하지 않는다. PDF가 이미지 기반이라 텍스트 추출이 실패하면 오류 메시지에 OCR 전처리가 필요하다고 안내한다.

### 9.2 Chat API

- 백엔드는 `POST /api/v1/chat`과 `POST /api/v1/chat/stream`을 canonical 경로로 제공해야 한다.
- 기존 `POST /chat`은 deprecated 호환 경로로 일시 유지해야 한다.
- 요청 본문에는 사용자 질문이 포함되어야 한다.
- `/chat` 응답과 `/chat/stream`의 최종 `done` 이벤트에는 다음이 포함되어야 한다.
  - 답변 텍스트.
  - 출처 목록.
  - 상태값.
  - 향후 외부 공식 검색이 필요한지 여부.
- `/chat/stream`은 답변 생성 중 `token` 이벤트로 부분 답변을 보내야 한다.
- 서버는 MVP에서 대화 기록을 DB, Redis 또는 프로세스 전역 메모리에 저장하지 않는다.
- 프론트엔드는 탭 단위 `thread_id`와 최근 대화 최대 4개를 요청에 포함한다.
- 근거 부족은 시스템 오류가 아니므로 HTTP 200과 `status: "insufficient_pdf_evidence"`로 반환한다.
- 인덱스 없음, 요청 형식 오류, OpenAI 호출 실패 같은 실행 문제는 HTTP 오류 응답으로 반환한다.

### 9.3 근거 기반 답변

- MVP 챗봇은 검색된 PDF 근거로만 답변해야 한다.
- 정책이나 사용 기준을 추측해서 만들면 안 된다.
- 근거가 부족하면 안내책자에서 확인되지 않는다고 답해야 한다.
- 정상 답변에는 최소 하나 이상의 출처가 포함되어야 한다.
- 검색은 기본적으로 top-k 5개 청크를 가져온다.
- `assess_evidence`는 다음 조건을 모두 만족할 때만 `answered_from_pdf`로 판단한다.
  - 검색 결과가 최소 1개 이상 존재한다.
  - 상위 검색 결과의 similarity score가 구현 시 정한 최소 기준 이상이다.
  - LLM evidence grader가 검색 청크만으로 질문에 답할 수 있다고 판단한다.
- LLM evidence grader는 `is_sufficient`, `reason`, `source_chunk_ids`를 포함하는 구조화된 결과를 반환해야 한다.
- 답변 생성에 사용되는 출처는 evidence grader가 충분하다고 판단한 청크로 제한한다.
- similarity score 기준값은 초기 구현에서 보수적으로 설정하고, 수동 검증 질문 결과를 보며 조정한다.

### 9.4 출처 표시

사용자에게 표시되는 각 출처에는 다음이 포함되어야 한다.

- 출처 타입: `pdf`.
- 제목: `청년수당 참여자 안내책자`.
- 페이지 번호.
- 관련 문단 excerpt.
- chunk_id.

### 9.5 향후 공식 출처 검색

MVP에는 공식 출처 검색을 위한 확장 지점만 둔다. 실제 검색 기능은 비활성화한다.

향후 검색 출처는 서울시, 청년몽땅정보통, 정부 또는 지자체 공식 페이지처럼 신뢰 가능한 공식 출처로 제한한다. 일반 웹 전체 검색은 의도 범위에 포함하지 않는다.

## 10. API 계약

### `GET /health`

백엔드 상태를 반환한다.

```json
{
  "status": "ok"
}
```

### `POST /api/v1/chat`

요청 예시:

```json
{
  "question": "청년수당 카드는 어디에서 사용할 수 있나요?",
  "thread_id": "browser-tab-uuid",
  "history": []
}
```

성공 계열 응답은 HTTP 200을 사용한다. 여기에는 PDF 근거로 답한 경우와 PDF 근거가 부족한 경우가 모두 포함된다.

정상 응답 예시:

```json
{
  "answer": "청년수당 사용처는 안내책자의 사용 기준에 따라 확인해야 합니다...",
  "sources": [
    {
      "type": "pdf",
      "title": "청년수당 참여자 안내책자",
      "page": 12,
      "excerpt": "관련 문단 일부...",
      "chunk_id": "pdf-page-12-chunk-2"
    }
  ],
  "status": "answered_from_pdf",
  "needs_external_search": false
}
```

근거 부족 응답 예시:

```json
{
  "answer": "안내책자에서 해당 내용을 확인하지 못했습니다. 최신 공식 안내 확인이 필요할 수 있습니다.",
  "sources": [],
  "status": "insufficient_pdf_evidence",
  "needs_external_search": true
}
```

오류 응답은 HTTP 상태 코드와 `{ "code": "...", "message": "..." }` 형태를 사용한다.

### `POST /api/v1/chat/stream`

요청 예시는 `/api/v1/chat`과 동일하다. 응답은 `text/event-stream` 형식을 사용한다.

```text
event: token
data: {"text":"청년수당은 "}

event: done
data: {"answer":"청년수당은 안내책자 근거에 따라 사용할 수 있습니다.","sources":[],"status":"answered_from_pdf","needs_external_search":false,"intent":"rag"}
```

예시:

```json
{
  "code": "index_missing",
  "message": "PDF 인덱스가 없습니다. 먼저 indexing 명령을 실행하세요."
}
```

## 11. 상태값

`status`는 HTTP 200 응답에서 챗봇 처리 결과를 나타낸다.

- `answered_from_pdf`: 충분한 PDF 근거로 답변을 생성했다.
- `insufficient_pdf_evidence`: 신뢰할 수 있는 답변을 만들 만큼 PDF 근거가 충분하지 않다.

오류 응답의 `code` 값은 실행 실패 원인을 나타낸다.

- `invalid_request`: 요청 형식이 잘못되었다.
- `index_missing`: FAISS 인덱스와 BM25 fallback용 PDF 텍스트를 모두 사용할 수 없다.
- `generation_error`: OpenAI 또는 런타임 문제로 답변 생성에 실패했다.
- `indexing_error`: PDF indexing 과정에서 실패했다.

## 12. 안전과 개인정보

- 화면에는 주민등록번호, 계좌번호, 전화번호, 개인 금융정보 등 민감정보를 입력하지 말라는 안내를 표시한다.
- 백엔드는 `.env` 값을 로그로 출력하지 않는다.
- OpenAI API key와 LangSmith API key를 출력하지 않는다.
- 질문, 대화 history, 답변, 검색 source 본문을 기본 애플리케이션 로그에 기록하지 않는다.
- LangSmith 추적이 켜져 있으면 질문/답변 텍스트가 추적에 남을 수 있으므로 민감정보 입력 방지 안내가 필요하다.
- 배포 전 LangSmith 입력·출력 마스킹과 reverse proxy request/response body logging
  비활성화를 확인한다.
- 답변 프롬프트는 검색 근거 밖의 추측을 금지해야 한다.

## 13. 성공 기준

MVP는 다음 조건을 만족하면 성공으로 본다.

- indexing 명령이 PDF에서 재사용 가능한 Chroma 인덱스를 생성한다.
- indexing 결과에 페이지 수, 빈 페이지 수, 추출 문자 수, 청크 수가 표시된다.
- 백엔드가 실행되고 health check에 응답한다.
- 프론트엔드가 실행되고 백엔드와 통신한다.
- 참여자가 질문을 입력하면 한국어 답변을 받는다.
- 정상 답변에는 PDF 페이지와 excerpt가 포함된다.
- PDF 근거가 부족한 질문에는 fallback 답변을 반환한다.
- 근거 없는 질문에는 출처 없는 일반 지식 답변을 생성하지 않는다.
- 새로고침하면 채팅 기록이 사라진다.

## 14. 수동 검증 질문

구현 후 실제 PDF 추출 결과를 보고 질문 문구는 조정한다. 초기 검증 범위는 다음을 포함한다.

- 청년수당 사용처.
- 활동기록서 제출.
- 자격상실 또는 참여 중단.
- 현금 사용 가능 여부.
- 증빙 또는 소명 관련 질문.
